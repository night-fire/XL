# Спецификация Языка X (v1.0)

> Данный документ описывает полную спецификацию языка X — доменно-специфического языка, предназначенного для разработки компиляторов и связанных инструментов. Язык X создавался изначально для целей системного программирования в области компиляции, оптимизации и трансляции, что отразилось на его синтаксисе, семантике и стандартной библиотеке.

## 1. Введение

Язык X обладает следующими целями и приоритетами:

1. Выразительность при описании языковых грамматик и трансформаций.
2. Статическая безопасность (строгая система типов, исключающая целые категории ошибок).
3. Высокая производительность с нулевыми накладными расходами при критичных участках кода.
4. Встроенная модель параллелизма и асинхронности.
5. Богатая метапрограммная подсистема (макросы, вычисления во время компиляции, шаблоны AST).
6. Простая интеграция с существующими экосистемами и возможностью встраивания в другие проекты.

## 2. Лексическая структура

### 2.1 Юникод

Исходный текст в UTF-8. Все идентификаторы и строковые литералы поддерживают полное множество символов Unicode. Ключевые слова и встроенные идентификаторы ограничены ASCII для совместимости.

### 2.2 Комментарии

- Однострочные: начинаются с `//` и продолжаются до конца строки.
- Многострочные: заключены между `/*` и `*/`, допускаются вложенные блоки.
- Док-комментарии: префикс `///` для API-документации.

### 2.3 Токены

Токены разделены пробелами или символами структуры. Подразумеваются категории: ключевые слова, идентификаторы, литералы, операторы и знаки пунктуации.

## 3. Синтаксис

Официальная грамматика задана в EBNF (см. Приложение A). Основные конструкты:

- **Модули**: единицы компиляции, определяемые директивой `module`.
- **Импорт**: оператор `import` поддерживает алиас-переименование и селективный импорт.
- **Объявления типов**: `type`, `struct`, `union`, `enum`.
- **Функции**: объявляются ключевым словом `fn` и поддерживают контракты (`requires`/`ensures`).
- **Генераторы кода**: специализированные блоки `generator` для описания шаблонов трансляции.

## 4. Система типов

### 4.1 Примитивные типы

- Целочисленные: `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`.
- Числа с плавающей запятой: `f32`, `f64`.
- Логический: `bool`.
- Символьный: `char` (кодовая точка Unicode).
- Специальный: `void` (отсутствие значения).

### 4.2 Составные типы

- **Структуры** — прямое размещение полей.
- **Юнионы** — альтернативное размещение.
- **Кортежи** — позиционное объединение.

### 4.3 Параметризованные и обобщённые типы

Явная универсальная квантификация с ключевым словом `forall`. Поддерживаются ограничения (`trait bounds`) и частичное применение параметров.

### 4.4 Расширенные возможности

- **Типы-функции** и сигнатуры высшего порядка.
- **Типы-уровня компиляции** (compile-time values) — значения, доступные только при компиляции.
- **Dependent Types (ограниченно)** — зависимости от констант времени компиляции.

## 5. Контроль потока

Операторы `if`, `match`, `while`, `for`, `loop`. Полная выражаемость: любой оператор является выражением и возвращает значение. Поддержка `break`, `continue`, `return`, меток.

## 6. Память и владение

Язык X использует смешанную модель управления памятью:

1. **Владение** (ownership) и заимствования (borrowing) в стиле Rust для системных компонентов и внутренних представлений AST.
2. **Сборщик мусора** (опционально подключаемый) для высокоуровневых фаз, где удобство важнее тонкого контроля.
3. **Региональная память** (arena allocation) для короткоживущих объектов, возникающих во время анализа.

Передача владения проверяется на этапе компиляции, исключая ошибки типа use-after-free.

## 7. Ошибки и исключения

Механизм `result` (тип-сумма `Ok`/`Err`) — основной способ передачи ошибок. Синтаксический сахар `?` для проброса. Исключения использованы только для аварийных неперехватываемых ошибок компилятора (`panic`).

## 8. Параллелизм и асинхронность

- **Зелёные потоки** и диспетчер задач.
- **Акторная модель** с почтовыми ящиками.
- **Каналы** с корректностью типов.
- `async`/`await` — работа с будущими значениями и параллельными фазами.

## 9. Метапрограммирование

### 9.1 Макросы

Гигиеничные, работают на уровне AST. Объявляются ключевым словом `macro`. Могут зависеть от phase-классов (экспандируются в определённой фазе).

### 9.2 Вычисления во время компиляции

Любая функция, тип или выражение, помеченное атрибутом `constexpr`, может быть исполнено компилятором для генерации константных данных, оптимизаций или кода.

### 9.3 Template AST

Встроенный DSL для манипуляции поддеревьями синтаксического дерева: pattern matching, замены, инкрементальные трансформации.

## 10. Специализированные конструкции для компиляторов

1. **`grammar`-блоки** — декларативное описание грамматики целевого языка с автоматическим генератором LR/LALR/GLR парсеров.
2. **`semantic`-блоки** — ассоциация семантических правил с узлами AST.
3. **`ir`-блоки** — декларативное описание промежуточных представлений и оптимизационных паттернов.
4. **`pass`-блоки** — определение последовательностей и условий запуска проходов оптимизации.
5. **`target`-модуль** — описание архитектурных особенностей целевой платформы (регистры, calling-convention, ABI).

## 11. Контракты и спецификации

Язык поддерживает проверяемые контракты: `requires`, `ensures`, `invariant`, `assert`. Контракты могут быть оценены как во время компиляции, так и в режиме runtime-assert для отладки.

## 12. Стандартная библиотека

- `core` — минимальное ядро (типы, память, ошибки).
- `ast` — структуры для деревьев разбора.
- `parse` — готовые парсеры для часто используемых форматов.
- `analysis` — алгоритмы CFG, SSA, data-flow.
- `opt` — общие оптимизации (dead-code, inlining, constant propagation).
- `codegen` — бэкенды к LLVM, WebAssembly, C и собственный JIT.
- `concurrency` — акторы, каналы, задачи.
- `serde` — сериализация/десериализация объектов компилятора.

## 13. Инструменты и экосистема

1. **`xbuild`** — пакетный и сборочный менеджер.
2. **`xdoc`** — генератор документации из док-комментариев.
3. **`xtest`** — единичные, свойственные и регрессионные тесты.
4. **`xbench`** — микробенчмаркинг и профилировщик фаз.
5. **`xfmt`** — автоформатирование кода.
6. **Язык-сервер** (LSP) с поддержкой линтера, подсказок и refactoring.

## 14. Безопасность и верификация

- **Статический анализ**: обязательный этап.
- **Формальная верификация**: интеграция с SMT-решателями; аннотации Hoare Logic.
- **Sandbox-режим**: ограниченное исполнение генераторов кода.

## 15. Процесс компиляции

1. Лексический анализ.
2. Построение AST и десугарация.
3. Семантический анализ (проверка типов, borrowing-анализ, контракты).
4. Преобразование AST → IR.
5. Последовательность оптимизаций, определяемых `pass`-блоками.
6. Генерация кода в целевой `target`.
7. Линковка и генерация финального артефакта.

## 16. Управление зависимостями и версии

Файлы манифеста `X.toml` определяют: имя пакета, версию, зависимости, профили сборки и настройки целевых платформ. Используется строгий `semver`.

## 17. Формальный семантический базис

Язык описывается строго-типизированной λ-исчислением с эффектами, расширенным системой владения. Semantics верифицированы с помощью Coq/Lean — формальные доказательства безопасности памяти и отсутствия data-races.

## 18. Стандартизация и расширения

Спецификация поддерживает versioning. Предложения изменений оформляются через RFC-процесс. Расширения совместимы по backward-compat.

## 19. Лицензия

Открытый стандарт MIT/Apache-2.0. Реализации могут использовать любую совместимую лицензию.

### Приложение A. Выдержки из EBNF

```
module      = "module" identifier ;
import      = "import" identifier [ "as" identifier ] [ "{" { identifier } "}" ] ;
type_decl   = "type" identifier type_body ;
struct_decl = "struct" identifier "{" { field } "}" ;
fn_decl     = "fn" identifier parameter_list [ return_type ] fn_body ;
// … дальнейшие правила опущены для краткости …
```

> Полная EBNF-грамматика доступна как отдельный артефакт `x.ebnf` в репозитории проекта.
